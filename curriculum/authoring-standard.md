# Стандарт учебного материала

Сессия считается реализованной не по факту существования README, а после content
review по этому стандарту.

## Обязательная структура

Каждый learner-facing README содержит:

1. Измеримый результат сессии.
2. Объяснение ментальной модели, а не только описание API.
3. Минимум два примера кода или конкретных сценария для code-темы.
4. Data flow, timeline или таблицу там, где важен порядок.
5. Сравнение с исходным стеком и границу аналогии — если курс переходный.
6. Разбор минимум двух типичных ложных решений.
7. Точное задание с ограничениями.
8. Отдельное описание автоматического check и agent review.
9. Проверяемый список DONE.

Теория должна занимать примерно 10–15 минут внимательного чтения. Более длинную
тему делите на несколько сессий.

## Практика

- Starter содержит одну целевую проблему.
- Acceptance test падает на starter по описанной причине.
- Минимальное корректное решение делает test зелёным.
- Test проверяет наблюдаемое поведение, а не имя hook или структуру реализации.
- Архитектурные ограничения, которые нельзя устойчиво проверить тестом, остаются в
  rubric и Codex-review.

## Quiz

- `quiz.json` хранит только машиночитаемые ids, варианты и настройки проверки.
- У quiz есть читаемый `quiz.md` с самостоятельным фрагментом кода или полным
  сценарием, порядком действий и вопросом.
- Вопрос не требует угадывать отсутствующий контекст: исходные значения, входные
  данные и действия показаны рядом.
- Свободное `reason` пишет учащийся своими словами; prompt не подсказывает формулу
  правильного объяснения.

## Подсказки и ответы

- Hints, quiz keys и reference solutions не лежат в рабочем дереве основной ветки.
- Support content хранится в отдельном Git ref `course-support`.
- `session:hint` раскрывает только следующий уровень и записывает это в progress.
- Нельзя выбрать level 2 или 3 напрямую.
- Level 1 напоминает концепцию; level 2 указывает область; level 3 показывает
  структуру исправления или reference fragment.
- Runner никогда не применяет reference solution автоматически.

Это защита от случайного раскрытия в IDE, а не криптографическая защита от владельца
repository.

## Проверка

Автоматическая проверка отвечает за воспроизводимые факты: ключ quiz, typecheck,
поведенческие tests, build и другие подключённые checks. Codex-review отвечает за
смысл: качество объяснения, соответствие ментальной модели, отсутствие обхода цели
и разумность публичных контрактов.

Сессия с `review` не завершается без актуального `PASS`, записанного после
последнего автоматического check.
