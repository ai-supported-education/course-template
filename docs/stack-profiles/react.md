# Профиль: React-курс

Этот профиль добавляется только к курсу по React или фронтенду, где React является
основой. В manifest используйте id `react` вместе с `software`, а для аудитории из
Vue — также с `transition`. Он не применяется к Java, сетям, алгоритмам или
hardware-курсам.

## Переход с Vue

Если аудитория знает Vue 3 Composition API, каждая ранняя React-тема должна
показывать не только «эквивалентный API», но и разницу модели: render snapshot,
явный state update, identity, effects и ownership. Аналогия полезна лишь пока
явно названа её граница; не описывайте React как Vue без шаблонов.

## FSD

Feature-Sliced Design — не prerequisite React и не общий industry law. Вводите его
после того, как учащийся уже умеет компоненты, state, data fetching и тесты. Сначала
покажите проблему ownership и зависимостей, затем дайте FSD как один из инструментов
границ приложения.

Для React-курса допустимо добавить FSD-сессии, правило review и реальный
архитектурный check (например, Steiger). Не добавляйте label `fsd` в manifest, пока
check не подключён и не проверен на starter/минимальном решении. В других курсах
архитектурные правила формулируются языком их стека, а не через FSD.

## Проверка

Публичное поведение компонента важнее имени hook и внутренней раскладки. Тесты не
должны заставлять учащегося копировать reference implementation. Для state/effect
тем объяснение проходит через render snapshot, setter, следующий render, commit и
effect; Vue-сравнение всегда заканчивается границей аналогии.
