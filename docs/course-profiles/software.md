# Profile: software

Используйте для карточек, где результатом является исполняемый код, конфигурация
сборки или наблюдаемое поведение программы.

## Контракт среды

- Зафиксируйте runtime, package manager и команды setup/check.
- Starter запускается до решения и содержит только целевую учебную проблему.
- Не прячьте обязательную загрузку, миграцию или ручную настройку после DONE.
- Токены, реальные credentials и production endpoints не входят в материалы или
  review packets; используйте `.env.example` и безопасные placeholders.

## Проверка

- Acceptance test сначала падает по ожидаемой причине, затем проходит после
  минимального корректного решения.
- Проверяется публичный контракт или пользовательское поведение, а не имя функции,
  выбранный API или структура файлов без отдельной архитектурной цели.
- Rubric описывает invariants и допустимые реализации. Style и необязательный
  refactor не блокируют PASS.
- Базовые `typecheck`, `unit` и `integration` реализованы для TypeScript/Vitest.
  Курс на другом языке заменяет registry runner и добавляет тест самого check.

Evidence обычно включает изменённые исходники и вывод реализованного check. Логи
успешного запуска не пишутся заранее в starter.
